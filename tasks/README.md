# Tasks

One file per item, the folder is the stage: `backlog/` (open, not started — `status: idea | ready | blocked |
waiting`), `wip/` (in flight), `done/` (closed, never rewritten), `dropped/` (closed without work; keeps its id,
carries `reason` + `reopen-when`), `decisions/` (`D-NNN`, `proposed → decided → superseded`). Ids come from one
repo-wide counter, assigned at intake and never reused; a file keeps its name through every `git mv`. A backlog
item is frontmatter plus 2–10 lines (what, why, done-when) — anything longer is a plan session, not a longer entry.
Every item passes backlog → wip → done, no stage skipped (`add` → `promote` → `close`, also in one session); a
drop is the only other exit. Closing a task proposes every follow-up to the maintainer and files the approved ones
as `backlog/` items now, or deletes them with a reason. Driven by `/tasks` (project-pal plugin); the section below
is generated by `/tasks check` — edit the files, never the section. Every numbered file here is mirrored one-way
into a GitHub issue by `scripts/sync-issues.py` — edit the file, never the issue.
